۰.۵ فرم اطلاعات پروژه

قبل از شروع فصل ۱، این فرم را برای پروژه خودتان کامل کنید. این فرم تمام مقادیری را که در طول کتاب به‌جای Placeholder استفاده خواهید کرد، در یک‌جا جمع می‌کند.

  • نام پروژه (Project Name): نام داخلی/فنی پروژه که در مستندات و مخزن استفاده می‌شود.
  • نام اپلیکیشن (App Name): نامی که زیر آیکون روی گوشی کاربر نمایش داده می‌شود.
  • نام شرکت/برند (Company / Brand Name): برای صفحه انتشار در مارکت و اطلاعات حقوقی.
  • آدرس وب‌سایت (Website URL): آدرس کامل سایتی که در WebView بارگذاری می‌شود.
  • دامنه اصلی (Main Domain): برای تشخیص لینک داخلی از خارجی در shouldOverrideUrlLoading.
  • نام پکیج (Package Name / Application ID): شناسه یکتای جهانی اپ؛ باید در Firebase و Gradle یکسان باشد.
  • Namespace: فضای نام کاتلین که در build.gradle تعریف می‌شود؛ معمولاً برابر applicationId.
  • رنگ اصلی برند (Primary Brand Color): برای تم، اسپلش و نوار ناوبری.
  • رنگ ثانویه برند (Secondary Brand Color): برای دکمه‌ها و لهجه‌های رنگی.
  • فایل لوگو (Logo File): تصویر مبنا برای تولید آیکون اپ و لوگوی اسپلش.
  • آدرس صفحه اصلی (Home URL): اولین تب ناوبری پایین.
  • آدرس دسته‌بندی‌ها (Categories URL): تب دوم ناوبری (در صورت وجود).
  • آدرس سبد خرید (Cart URL): برای اپ‌های فروشگاهی؛ در غیر این صورت حذف شود.
  • آدرس حساب کاربری (Account URL): برای مدیریت پروفایل و ورود کاربر.
  • آدرس ورود (Login URL): برای بررسی صحت پایداری نشست (Cookie).
  • سیاست حریم خصوصی (Privacy Policy URL): الزامی برای اکثر مارکت‌ها.
  • شرایط استفاده (Terms of Service URL): توصیه‌شده برای اپ‌های تجاری.
  • سرویس‌دهنده نوتیفیکیشن (Push Notification Provider): مثلاً Webpushr، OneSignal یا سرویس اختصاصی.
  • نام پروژه فایربیس (Firebase Project Name): نام نمایشی در Firebase Console.
  • شناسه پروژه فایربیس (Firebase Project ID): برای اتصال google-services.json.
  • مخزن گیت‌هاب (GitHub Repository): مسیر owner/repo برای CI/CD.
  • شاخه اصلی (Main Branch): معمولاً main؛ برای تنظیم Workflow.
  • نسخه هدف اندروید (Target Android Version): targetSdk — آخرین نسخه پایدار توصیه می‌شود.
  • حداقل نسخه اندروید (Minimum Android Version): minSdk — بسته به بازار هدف کاربران.
  • بازار هدف (Target Market): مثلاً Google Play، Cafe Bazaar یا هر دو.
  • توضیحات اپلیکیشن (Application Description): متن معرفی برای صفحه انتشار در مارکت.

این فرم را به‌جای پرکردن ذهنی، در یک فایل جداگانه (مثلاً project-info.md) در همان مخزن گیت‌هاب پروژه ذخیره کنید.

۱ مفاهیم پایه: وب‌سایت، PWA، WebView، TWA

موضوع اصلی این کتاب «اپلیکیشن اندروید از نوع WebView» است. اما چون این مفهوم اغلب با PWA و TWA اشتباه گرفته می‌شود، لازم است پیش از هر چیز چهار مفهوم را دقیق از هم جدا کنیم.

۱. وب‌سایت (Website)

مجموعه‌ای از صفحات HTML/CSS/JavaScript است که از طریق مرورگر و با آدرس اینترنتی در دسترس است. هیچ نصبی روی گوشی ندارد و هر بار باید در مرورگر باز شود.

۲. PWA (Progressive Web App)

یک وب‌سایت است که با افزودن دو فایل — manifest.json و Service Worker — قابلیت‌های شبه‌اپلیکیشن پیدا می‌کند: افزودن آیکون به صفحه اصلی گوشی، کارکرد محدود آفلاین، و در برخی مرورگرها نوتیفیکیشن پوش.

۳. Android WebView

یک کامپوننت بومی اندروید (android.webkit.WebView) است که درون یک اپلیکیشن کاتلین/جاوا واقعی جاسازی می‌شود و یک صفحه وب را داخل آن رندر می‌کند. برخلاف PWA، این یک اپلیکیشن بومی واقعی است که در Google Play/Cafe Bazaar نصب می‌شود، APK/AAB واقعی دارد، به API های بومی اندروید دسترسی کامل دارد.

✅ روش قابل بازتولید — REUSABLE METHOD

موضوع محوری این کتاب همین مسیر است: ساخت یک اپلیکیشن بومی اندروید با یک WebView سفارشی در مرکز آن — نه یک PWA و نه ترکیب گمراه‌کننده «WebView PWA App».

۴. TWA (Trusted Web Activity)

یک روش میانه است: یک اپلیکیشن بومی اندروید بسیار سبک که به‌جای WebView سفارشی، از موتور Chrome نصب‌شده روی گوشی برای نمایش تمام‌صفحه سایت استفاده می‌کند. تقریباً هیچ کدنویسی UI بومی در آن وجود ندارد.

۲ از الزامات پروژه تا مشخصات فنی

قبل از باز کردن Android Studio، باید مشخص شود اپلیکیشن دقیقاً چه کاری باید بکند. این مرحله دو گام دارد: ابتدا «الزامات» به زبان ساده نوشته می‌شود، سپس این الزامات به یک «مشخصات فنی» دقیق و قابل اجرا تبدیل می‌شود.

الزامات پروژه — سوالاتی که باید پاسخ دهید

  • کدام بخش‌های سایت باید در ناوبری پایین اپ باشند؟
  • آیا نشست ورود کاربر باید بین اجراهای مختلف اپ حفظ شود؟
  • آیا نوتیفیکیشن پوش لازم است؟ از چه سرویسی؟
  • رفتار دقیق دکمه Back در صفحه اصلی و صفحات داخلی چه باید باشد؟
  • آیا محدودیت خاصی روی حجم نهایی APK یا زمان بارگذاری اولیه وجود دارد؟
  • آیا نیاز به پشتیبانی از حالت آفلاین با پیام و دکمه تلاش مجدد وجود دارد؟

۳ ابزارها از صفر: Android Studio، Kotlin، SDK، JDK، Gradle و AGP

Android Studio

محیط توسعه رسمی گوگل برای اندروید؛ ویرایشگر کد، ابزار طراحی رابط، شبیه‌ساز و ابزارهای دیباگ را در یک برنامه ترکیب می‌کند.

Kotlin

زبان برنامه‌نویسی رسمی و توصیه‌شده گوگل برای اندروید؛ جایگزین مدرن‌تر جاوا با نحو کوتاه‌تر و ایمنی بیشتر در برابر Null.

Android SDK

مجموعه کتابخانه‌ها و ابزارهایی که برای کامپایل و اجرای کد روی اندروید لازم است؛ شامل نسخه‌های مختلف API اندروید.

JDK (Java Development Kit)

ابزار کامپایل کد جاوا/کاتلین به بایت‌کد قابل اجرا روی ماشین مجازی جاوا؛ Gradle و AGP به آن نیاز دارند.

Gradle و Android Gradle Plugin (AGP)

Gradle موتور بیلد پروژه است؛ AGP پلاگینی است که قوانین خاص اندروید (کامپایل منابع، تولید APK) را به Gradle اضافه می‌کند.

⚠️ هشدار

این جدول یک راهنمای کلی و مربوط به زمان نگارش این کتاب است، نه یک عدد ثابت و همیشگی. AGP معمولاً هر سال یک نسخه اصلی جدید منتشر می‌کند؛ همیشه پیش از شروع پروژه، صفحه رسمی «Android Gradle Plugin Release Notes» را بررسی کنید.

۴ ساختار پروژه: Module، Namespace، Application ID و نسخه‌های SDK

Module

یک واحد مستقل بیلد در پروژه اندروید (معمولاً پوشه app/). برای یک اپ WebView ساده، یک Module به نام app کافی است.

Namespace

فضای نام کاتلین/جاوا که کلاس‌های تولیدشده (مثل R و BuildConfig) در آن قرار می‌گیرند؛ در build.gradle ماژول تعریف می‌شود.

Application ID / Package Name

شناسه یکتای جهانی اپلیکیشن شما در گوگل‌پلی/بازار و در Firebase؛ پس از اولین انتشار عملاً غیرقابل تغییر است.

⚠️ هشدار

هرگز applicationId موقت «برای تست» انتخاب نکنید. تغییر آن بعد از انتشار یعنی از دست‌دادن تمام نصب‌ها، امتیازها و کاربران فعلی — چون از نگاه مارکت، این عملاً یک اپلیکیشن کاملاً جدید محسوب می‌شود.

minSdk / targetSdk / compileSdk

  • minSdk: پایین‌ترین نسخه اندرویدی که اپ روی آن نصب می‌شود.
  • targetSdk: نسخه‌ای که اپ برای آن بهینه و تست شده است.
  • compileSdk: نسخه SDK ای که با آن کد کامپایل می‌شود.

۵ AndroidManifest.xml از صفر

AndroidManifest.xml مهم‌ترین فایل پیکربندی هر اپلیکیشن اندروید است. سیستم‌عامل پیش از نصب یا اجرای اپ، این فایل را می‌خواند تا بفهمد اپ از چه اجزایی تشکیل شده، چه مجوزهایی نیاز دارد، و کدام Activity باید هنگام باز شدن اپ اجرا شود.

اجزای اصلی Manifest

  • Application: تگ ریشه اصلی تنظیمات کلی اپ (آیکون، نام نمایشی، تم).
  • Activity: هر صفحه قابل مشاهده اپ؛ Activity اصلی باید intent-filter با action=MAIN و category=LAUNCHER داشته باشد.
  • Service: یک جزء بدون رابط کاربری که در پس‌زمینه کار می‌کند؛ مثل FirebaseMessagingService.
  • Broadcast Receiver: جزئی که به رویدادهای سیستمی گوش می‌دهد.
  • Intent Filter: مشخص می‌کند یک Activity/Service به چه نوع Intent هایی پاسخ می‌دهد.
⚠️ هشدار — exported

از اندروید ۱۲ (API 31) به بعد، هر Activity/Service/Receiver که دارای intent-filter است، باید مقدار android:exported را صریحاً true یا false تعیین کند؛ در غیر این صورت بیلد با خطا متوقف می‌شود.

نمونه کامل Manifest

XML
<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.INTERNET" />
    <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
    <uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
    <application
        android:name=".[PROJECT_NAME]Application"
        android:allowBackup="true"
        android:icon="@mipmap/ic_launcher"
        android:roundIcon="@mipmap/ic_launcher_round"
        android:label="@string/app_name"
        android:theme="@style/Theme.[PROJECT_NAME]"
        android:usesCleartextTraffic="false">
        <activity
            android:name=".SplashActivity"
            android:exported="true"
            android:theme="@style/Theme.[PROJECT_NAME].Splash">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>
        <activity
            android:name=".MainActivity"
            android:exported="false"
            android:launchMode="singleTop"
            android:configChanges="orientation|screenSize|keyboardHidden"
            android:theme="@style/Theme.[PROJECT_NAME]" />
        <service android:name=".MyFirebaseMessagingService" android:exported="false">
            <intent-filter>
                <action android:name="com.google.firebase.MESSAGING_EVENT" />

۱۰ Firebase و Firebase Cloud Messaging (FCM) از صفر

❓ سوالات متداول

اگر Placeholder ای را فراموش کنم جایگزین کنم چه اتفاقی می‌افتد؟
کد یا سند تولیدشده یک مقدار نمادین بی‌معنی خواهد داشت که به‌محض اجرا یا بررسی، بلافاصله قابل‌تشخیص است. همیشه بعد از دریافت هر خروجی از AI، یک بار سریع دنبال کروشه‌های باقی‌مانده بگردید.
آیا لازم است فصل‌ها را دقیقاً به همان ترتیب کتاب بخوانم؟
برای اولین‌بار بله، چون هر فصل روی مفاهیم فصل قبل بنا می‌شود؛ برای مراجعه بعدی، می‌توانید مستقیم سراغ فصل موردنیاز بروید.
آیا GitHub Actions برای مخازن خصوصی هم رایگان است؟
بله، تا یک سهمیه ماهانه مشخص (که برای این نوع پروژه ساده معمولاً کافی است) رایگان است؛ فراتر از آن هزینه‌بر می‌شود.
اگر Keystore را گم کنم ولی از Google Play App Signing استفاده کرده باشم، چه اتفاقی می‌افتد؟
گوگل یک مسیر رسمی بازیابی از طریق پشتیبانی Play Console دارد، چون خودش کلید نهایی امضای انتشار را نگه می‌دارد؛ این دقیقاً همان مزیتی است که این سرویس را ارزشمند می‌کند.
چند دستگاه فیزیکی واقعاً برای تست کافی است؟
حداقل دو برند متفاوت (یکی با محدودیت‌های سخت‌گیر مثل شیائومی/هوآوی) پوشش خوبی برای اکثر مشکلات رایج OEM می‌دهد؛ ایده‌آل بیشتر، اما این حداقل عملی است.
آیا می‌توان همزمان هم PWA و هم اپ WebView سفارشی داشت؟
بله، کاملاً؛ این دو رقیب هم نیستند — PWA برای کاربران دسکتاپ/بدون‌نصب و اپ WebView برای حضور کامل در مارکت با قابلیت‌های بومی، می‌توانند مکمل هم باشند.
